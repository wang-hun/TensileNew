# 联机协议（识别程序 ↔ 机器上位机）

一句话：**识别程序做服务端**，上位机连上来保持一条 **TCP 长连接**，所有指令和结果都在这条连接上收发；
一行一条命令，UTF-8，以 `\n` 结尾（`\r\n` 也认）。

```
┌────────────┐  TCP(默认 800) 长连接，连上一直不关     ┌──────────────┐
│  机器上位机 │ ── start ─────────────────────────────▶ │  识别程序     │
│  (客户端)   │ ◀───────────────────────────── start ── │  (服务端)     │
│             │ ── check [图片路径] ──────────────────▶ │              │
│             │ ◀─────────────── skip / stop / error ── │              │
│             │ ── end ───────────────────────────────▶ │              │
│             │ ◀─────────────────────────────── end ── │              │
└────────────┘                                          └──────────────┘
```

界面顶栏「收发说明」按钮里有同样的说明，可直接给上位机对接方看。

## 1. 端口

| 用途 | 默认 | 在哪里改 |
|---|---|---|
| TCP 联机端口（识别监听，上位机连） | 800 | 界面「联机…」→ TCP 端口 |
| HTTP 检测接口端口（网页/其它程序用，联机不需要） | 5080 | 界面「联机…」→ API 端口 |

设置都存 `%APPDATA%\RingInspect\settings.json`。

## 1.1 配置持久化

改完「联机设置」点**保存**，会立刻写盘，下次启动自动生效（不用重新填）：

| 存了什么 | 存了之后的表现 |
|---|---|
| TCP 端口 + 「是否自动监听」 | 启动时按保存的端口自动开监听；在窗口里点「停止监听」会记成不自动开 |
| API 端口 | 启动时按保存的端口起 HTTP 接口（改了端口自动重启接口） |
| 默认文件夹 + 默认文件名 | `check` 不带路径时，检测这个文件（上位机原地覆盖那张图） |

- 保存成功，窗口底部会显示 `已保存到 …settings.json（下次启动自动生效）`；
  写不进去（目录只读 / 权限不足）会显示 `写入配置文件失败：<原因>`，此时设置只在当前进程有效。
- 写的位置按顺序找第一个能写的：`%APPDATA%\RingInspect\settings.json` →
  `%LOCALAPPDATA%\RingInspect\settings.json` → 程序目录下的 `settings.json`；
  提示里显示的是**实际**写入的那个路径（多份存在时，启动读最近改过的那份）。
- 也可以直接用环境变量 `RINGINSPECT_SETTINGS` 指定位置（便携部署、统一放 U 盘/共享盘时用）：
  ```powershell
  $env:RINGINSPECT_SETTINGS = 'D:\RingInspect\settings.json'
  ```
- 配置文件示例：
  ```json
  {
    "TcpPort": 800,
    "ApiPort": 5080,
    "DefaultFolder": "D:\\相机图",
    "DefaultFileName": "shot.bmp",
    "AutoStartTcp": true
  }
  ```
- 命令行 `--tcp= --api= --folder= --filename=` 只是**临时覆盖**、不落盘；
  想让它们落盘，加 `--savelink` 启动一次（写入后自动退出），用于批量部署：
  ```powershell
  RingInspect.Wpf.exe --tcp=800 --folder=D:\相机图 --filename=shot.bmp --savelink
  ```

## 2. 上位机 → 识别

| 命令 | 含义 | 识别的动作 |
|---|---|---|
| `start` | 开始生产 | 进入「接收中」，回一行 `start` |
| `check` | 检测默认文件 | 检测「默认文件夹 + 默认文件名」，回一行结果 |
| `check <路径>` | 检测指定图片 | 检测这张图，回一行结果；路径带空格时整体加双引号 |
| `radius` | 测默认文件的内、外圆半径 | 只回半径，不做缺陷判定 |
| `radius <路径>` | 测指定图片的内、外圆半径 | 只回半径，不做缺陷判定 |
| `end` | 结束/停止 | 退出「接收中」，回一行 `end`；之后再来 `check` 回 `error` |

- `radius` 返回内圆半径和外圆半径（像素），不受 `start` 和检测开关限制，随时可发。
- 其它行：记录日志后忽略，不回复。
- **发一条等一条**：`check` / `radius` 之后要等回执再发下一条；同一条连接上的指令按收到顺序处理。
- 断线重连后需要重新发 `start`。

## 3. 识别 → 上位机

| 回复 | 什么时候发 | 上位机动作 |
|---|---|---|
| `start` / `end` | 收到 start / end 的回执 | 确认 |
| `skip` | 本次 **无错**（判定 OK，无缺陷） | 继续跑 |
| `stop <个数> <坐标…>` | 本次 **NG**（有缺陷） | 执行停机逻辑；坐标见下 |
| `radius <内圆半径> <外圆半径>` | 收到 `radius` 且拟合成功 | 内圆半径、外圆半径，像素，两位小数 |
| `error <原因>` | 检测失败：读不到文件、解码失败、找不到圆环、还没 `start`、检测开关关着、路径不合法 | 按自己的策略处理，一般不当 NG 停机 |

`stop` 后面的缺陷坐标格式：

```
stop <缺陷个数> <中心x>,<中心y>,<左>,<上>,<右>,<下> <中心x>,<中心y>,<左>,<上>,<右>,<下> …
```

- 全部是像素，一位小数，原点是图片左上角。
- 每个缺陷 6 个数：外框中心点和外框左/上/右/下边界。
- 多个缺陷用空格隔开，顺序按角度。
- 没有缺陷但判定为 NG 时只回 `stop`（正常情况不会出现）。

例：`stop 2 2260.5,1432.5,1901.0,1040.0,2620.0,1825.0 520.3,630.1,500.0,600.0,540.6,660.2`

- `error` 后面的原因只有一行，用于日志排查，可以不解析。
- 回执只发给发这条指令的连接，多台上位机互不串台。

## 4. 一次完整交互

```
上位机 → start
识别   → start
上位机 → check
识别   → stop 1 2260.5,1432.5,1901.0,1040.0,2620.0,1825.0
上位机 → check
识别   → skip
上位机 → check D:\img\cam02.bmp
识别   → error 文件不存在：cam02.bmp
上位机 → radius
识别   → radius 383.53 498.04     （内圆半径 / 外圆半径，像素）
上位机 → end
识别   → end
```

检测耗时参考：12.2 MP（35 MB BMP）约 80~100 ms；2448×2048（15 MB）约 45~60 ms。

> 文件被上位机「原地覆盖」时：识别会连续重试 3 次（每次间隔 30 ms），并且核对读取前后
> 文件长度/修改时间是否变化，避免把半张图当成品检。可用环境变量 `RINGINSPECT_FAST_RETRY` 调次数。

## 5. 界面上的相关设置

「联机…」窗口里可以改：

- **TCP 端口** + 启动/停止监听，并显示「监听中 :800｜上位机 1 个｜接收中」
- **API 端口**（保存后按新端口重启 HTTP 接口；联机不使用它）
- **默认文件夹 / 默认文件名**（`check` 不带路径时用它）
- **联机日志**：收发原文、每次判定与耗时都记在这里，主界面底部状态栏也同步显示。

主界面右上角有联机状态灯：灰=未监听，黄=监听中待 start，绿=接收中。

## 6. 自测

```powershell
# HTTP 接口自测（与联机无关）
curl http://127.0.0.1:5080/api/health

# 长连接自测：连上后用任意 TCP 工具依次发 start / check / end，看回执
```

WPF 启动参数（自测用，不落盘）：`--tcp=18001 --api=http://127.0.0.1:15081
--folder=E:\Opencv --filename=xx.bmp --noTcp`
